# 汇报解说片工作流

## 1. 需求确认
- 问清：观众（谁看、什么级别）、目的（要对方产生什么判断/想要什么）、时长、交付日期。
- 记下客户命名规则（例：产品对客户叫「智慧车间项目」，不用内部代号）、品牌色、禁用词。

## 2. 素材唯一真源
- 以定稿 PPT 与方案文档为唯一来源；用 python-pptx 抽文字、LibreOffice 渲页面图。
- 片中每个数字、每句结论都要能在来源里找到出处。源文件只读。

## 3. 故事线
- 先写一条因果链（例：技术变革 → 重建数据与 AI 体系 → 新认识客户与门店 → 服务方式改变 → 新系统 → 具体服务落地 → 路线图）。
- 每章一句话说清它承接上一章什么、引出下一章什么；新增章节必须改前后过渡，不能突兀。
- 有标杆案例、效果样机的，放在观众最想“自己也要”的位置。

## 4. 旁白
- 由 Claude Code 写：提示词用英文（美式表达），要求中文输出。
- 再做去 AI 腔处理（humanizer）：短句、口语、无套话；逐句对来源核数字。

## 5. 分镜
- 内容镜头用自家图表、架构图、产品样机页（动画化）。
- 即梦只做少量氛围镜头：720p、每镜先报积分、设上限、经批准再跑。
- 只出现客户自家品牌车型，不得有别家车、车标、水印、可读乱码文字（文字后期加）。
- 场景要真实（例：售后车白天从道闸进场开进维修区，不会开进展厅；别用不合理夜景）。

## 6. 配音
- 出 3–8 条试听样本让用户挑；默认 edge-tts（例：zh-CN-YunjianNeural +10%）。付费音色需批准。

## 7. 制作
- 用 huashu-art-motion 或 ffmpeg/HTML+playwright 录屏合成。
- 混音按 video-production-workflow：说话时背景乐压低，成片约 -16 LUFS，真峰值 ≤ -1.5 dBFS；字幕与配音同一时间轴。
- 可复用的上一版镜头直接拷贝到新项目，不改旧版目录。

## 8. 硬规矩检查
- 无编造数字；无内部附录/内部比例；对外命名正确；画面无 AI 自我解释文字；场景合理；无别家品牌。

## 9. 自检
- 出 contact sheet（每镜一帧）；新改镜头抽 30/60/92% 帧逐张看。
- 同步检查：关键词出现后 ~0.9 秒抽帧，核对字幕/画面字/配音一致。
- 车标/水印扫描（即梦镜头逐帧看）。不过关不交付。

## 10. 交付与版本
- 每版独立目录 `video_vN/`：成片 mp4、contact sheet、旁白稿、字幕、`project/`、REPORT.md（改了什么、花了多少积分、遗留问题）。
- 交付时说清：时长、改动、花费、还不理想的地方和改法成本。

## 11. 运行
- 长任务用 `setsid nohup … < /dev/null &` 挂起，日志落文件。
- 只按确切 PID 停自己的进程，绝不 pkill/killall。
- 盒子负载高时一次只跑一个渲染；浏览器、录屏跑完即退出。
- 省 Claude 额度：能复用的不重做，小改用脚本不用模型。
