# P3 声音、混音和中韩字幕

输入为已登记干声、原文与镜头时钟；可信程序压低人声下的原创背景乐，调整响度，烧录已审字幕，再测量最终AAC（有损音频）编码。它复用已有网关、任务身份、资源锁、失败退款和不可变交付，不调用翻译或在线配音。真实译审记录与客户素材审批分别管理；文件通过仍是 `NOT_REVIEWED`（待人工审阅）。

## 中文选声与合成语速

原有云希、晓晓保留，新增云健 `microsoft_yunjian` → `zh-CN-YunjianNeural`。适配器另支持韩语 `microsoft_injoon` → `ko-KR-InJoonNeural`，不在通用中文表单中混入韩语旁白。实际可用性须查运行时音色目录；安装适配器不等于服务永远可用。保留 `edge-tts==7.3.1` 及显式启用开关；无应用层自动重试或声音回退，SDK（服务调用库）可能为时钟偏差自动重试一次403。

真实创作表单、HTTP（网页接口）的 `video_voice_rate` 与MCP（工具接口）的 `voice_rate` 均可选 `-6%`、`+0%`、`+10%`。默认 `-6%` 保持旧请求身份；非默认参数参与幂等身份、持久化、重试、声音缓存和交付核验。语速传入合成器，不后期拉伸、截断或以其他声音替代。配音装不进镜头仍失败。长片 `approved_local` 直接使用登记音轨，拒绝从表单改变语速；应先在包外完成短试听和人工选声，再合成/登记完整口播。

三版同稿试听见 `gateway/static/voice-samples/README.md`。选择前不得新合成全片；试听成功、文件通过都不代表用户已选声。

2026-10-23用户已明确选B（云健、+10%）并授权完整中文样片。此前20段干声因每秒4字规则被真实接口422拒绝，只生成带阻断标记的私有审阅片；这些文件和拒绝记录保留为历史。后续核查确认：基线 `51ba24c` 的 `narration_density` 明确说明它只是合成前规划预算；交接要求使用实测音频，没有规定4字录音上限。本地P0把规划估计误用于已登记录音，现已纠正。

规划阶段继续保留原有字数预算，限制尚未合成的稿件规模。已登记长片不再按字数推断录音是否安全，而检查真实48kHz单声道16位PCM样本、摘要与账户归属、每镜2–20秒、前后各6–12帧留量、24帧时钟及总时长严格闭合。最终AAC仍须独立解码、逐镜波形位置相关度≥0.90、总样本误差≤1024、综合响度−17至−15 LUFS及真峰值≤−3.8 dBTP；字数不能证明发音或可懂度，文件通过也不能替代人工审听。

`tools/exec_pitch_cn_acceptance.py --root <全新沙盒目录> --cache <已选B版缓存目录> --runtime <本机配置JSON>` 核对原人工选择、原稿、声音/语速缓存身份和音频摘要，再经原HTTP网关、隔离Worker、HTML分块、混音、字幕、独立验收、沙盒结算及鉴权下载。此入口没有合成或规划调用路径，缓存缺失或变化直接失败。它不改变韩语译审或客户素材授权。

## 长片专用混音配置

登记内容包可添加：

```json
"voice_mix": {"profile":"exec_pitch_p3","music":"original_ducked","input_audio":"dry_dialogue"}
```

`music` 只允许 `none`（无背景乐）或 `original_ducked`（原创背景乐随实际人声能量压低）。输入必须是操作者确认的干声；不把已有混合音轨冒充干声叠加背景乐。底乐不含外部录音或付费素材。每50毫秒测量人声能量，含前后400毫秒保持及平滑过渡；末尾人声不会绕回影响开场。轻度快速动态压缩＋双遍响度调整保留编码余量；允许一次依据已编码音轨余量的本地校正。增益余量足够时只调增益；瞬间峰值令增益不足以达标时，同一次校正采用固定目标的动态归一化。之后重新测量，不循环编码直到碰巧通过，不重请求声音。人声或底乐削波、无法同时满足响度和真峰值时失败。

最终编码及字幕烧录后的综合响度必须在−17至−15 LUFS（约−16），真峰值必须≤−3.8 dBTP。滤镜目标值不能代替最终测量。无此字段的旧内容包继续使用原≤−1.5门槛，不重新编码或将旧片改称P3达标。

## 中韩映射与审批

`bilingual` 字段存在即须 `enabled=true`，必须启用P3混音和字幕烧录。唯一支持的声音安排为 `single_language_track`（整片一条中文或韩语旁白），不混叠两条旁白。韩语旁白须登记InJoon；中文可云希、晓晓或云健。媒体已在包内，渲染不新请求合成。

```json
"bilingual": {
  "enabled":true,"narration_language":"ko-KR",
  "arrangement":"single_language_track","voice":"microsoft_injoon","rate":"+0%",
  "record_type":"human_record","approval_sha256":"<译审JSON字节摘要>",
  "cues":[{"shot_num":1,"start_frame":0,"end_frame":72,"zh":"<原口播分句>","ko":"<已审韩语分句>"}]
}
```

`cues` 为人工核对、显式登记的分句时间，24帧同一时钟，无重叠，每句至少半秒，不能跨镜头。每镜中文拼接须严格等于原口播，字幕覆盖实际音轨范围，同一口播内不留未说明间隙。两种语言各一行：横屏每行最多30字符，竖屏18字符；超出时须提供已审分句及时间，不自动按字数编造对齐。当前不是逐字对齐证明。

`manuscript.json` 与 `content_manuscript.md` 保留中文原文及论证，映射随完整内容包交付。`narration.txt` 按选定旁白语言输出，韩语旁白不会误交中文口播文本。

审批在同一只读登记目录 `evidence/<approval_sha256>.json`，字段严格为：`record_type`、`reviewer`、`owner`、`source_sha256`、`mapping_sha256`、`audio_sha256`、`scope`、`approved_at`、`expires_at`。`mapping_sha256` 是去掉 `approval_sha256` 后完整映射经 `canonical()` 的摘要；音频摘要数组按镜头排列。`owner` 为账户摘要；`scope` 固定 `translation_captions_and_single_language_audio`，时间须含时区且当前有效。逐项绑定原文、完整映射、声音语言/语速和实际音轨。

只有可信操作者可写登记目录；摘要保证字节一致，**不为自称人工批准的JSON提供独立签名认证**。客户端、模型、测试工具不能签发人审许可。真实素材要求 `human_record`，合成测试要求 `test_fixture`；后者不得升级为真实译审或客户批准。没有合法记录时明确缺失，不能自动翻译后标“已审”。

## 字体与烧录

配置操作者本地合法安装的单一TTF/OTF字体 `NBPPT_BILINGUAL_FONT` 与 `NBPPT_BILINGUAL_FONT_SHA256`，字形检查需 `requirements-bilingual.txt`。不自动下载或发布字体。入场、渲染、独立交付均校验摘要和全部实际中韩字形，缺少配置、运行时、韩文字形或libass（字幕渲染库）时失败。

字幕由平台固定ASS（字幕排版）模板生成，无客户端代码。两行白字暗底，左右与底部各6%安全边距，横屏28像素、竖屏32像素；关闭自动换行，拒绝容量超限。字体仅复制进任务临时目录，最终不附带字体。烧录复制原AAC流，之后完整解码和重测响度。字体、映射审批摘要随 `source_manifest.json`（来源记录）交付。

本轮切点检查修复了24帧时钟转字幕时间时的首帧旧字幕问题：仅烧录临时副本向下量化至libass原生10毫秒精度，确保不会把新字幕推迟到切点之后。下载VTT及其原时钟证据不变；中韩ASS也使用相同向下量化。此修复不建立逐字对齐证据。

单语字幕在原两行容量内均衡换行，避免片尾句号单占一行；不改变原稿字符、字幕时间和已编码音轨。

## 验证边界

`python tools/exec_pitch_voice_acceptance.py --root <全新沙盒目录> --runtime <本机配置JSON>` 走实际HTTP创建、隔离Worker（执行服务）、浏览器分块、原创底乐、AAC编码、中韩烧录、独立文件门槛、结算与鉴权下载。夹具明确是测试音调和测试译文，不能用于韩语发音或人工译审验收。真实韩语映射、其他任务的选声及客户内容仍须各自的真实证据。后续逐字同步、客户规则和影视质量不由本阶段代验。
