## 当前P1：离线HTML分块动态镜头（本地候选）

`exec_pitch`（高管汇报长片模式）的新任务默认使用 `html_chromium`（浏览器动态渲染）。已登记因果稿与口播节拍 → 严格的画面数据 → 平台自己的HTML/SVG（网页与矢量画面）模板和Lottie（矢量动画播放器）→ 96帧以内的片段 → 帧数、首尾帧、音轨与字幕复核 → 原有原子发布及结算。旧短片与Claude实景路径保持原渲染器；`registered_video`显式保留P0登记视频剪辑。历史P0失败任务重试仍用原剪辑器，新HTML任务则保存已解析的引擎，重试不会因默认值变化而换引擎。

新增九类可信画面：标题/具体事件开场、对比、流程、架构层叠、任务枢纽、时间线、CRM（客户管理系统）画面框、B-roll（辅助实景）衬板、片尾标识。P1输入只选版式、标题、对象标签和焦点编号；不接收HTML、JS（脚本）、CSS（样式）、动画表达式、网址或文件路径。P1缺截图时的模板占位仅保留作调试；P2正式内容包里的产品截图镜头缺证就拒绝，不把占位变成客户交付。

以24帧为唯一时钟，每次渲染直接定位到镜头内指定帧；Lottie关闭自动播放和子帧插值，用 `goToAndStop(frame,true)`定位。主动从镜头尾回到首帧，要求PNG（无损画面）摘要严格一致。固定软件绘制、字体加载屏障、浏览器版本及二进制摘要，避免GPU（图形处理器）缓存造成相同状态的边缘像素差异。每块最多96帧，连续覆盖原口播时间轴；分块不重置镜头内部时间。

Chromium（浏览器内核）使用全新任务内配置目录，沙箱保持启用，禁止 `--no-sandbox`。页面离线、拦截网络、屏蔽服务工作线程，并通过CSP（网页资源限制）只允许平台脚本、内嵌字体和图片；不读取用户日常浏览器配置。配置、HTML快照、原始首尾帧、日志、浏览器临时文件与缓存均在任务的 `html-render/`。沿用原单任务渲染租约和进程取消；真实取消回归检查本任务浏览器进程退出。

`render_chunks.json`进入不可变交付清单。独立校验器检查时间轴无缺口/重叠、每块摘要、首尾帧及最终编码切点帧；压缩后画面比较限定在字幕以上区域，平均像素差上限8，原始重复定位仍要求逐字节一致。大量切点用平衡表达式提取，避免FFmpeg解析深度溢出。配音继续复用登记音频并独立进行P0波形节拍比对；这不代替P4逐字对齐、全片画面或客户规则验收。

运行依赖及复现见 [P1运行说明](VIDEO_AUTHORING.md#p1-动态引擎配置与复现)。当前使用Playwright（浏览器控制库）1.62.1、Lottie 5.13.0；前者有锁文件，后者随仓库保留MIT许可及摘要。参考过花叔原始动画语法与GSAP（动画时间控制库）/Lottie官方规则，未安装或执行第三方技能脚本。素材/字体/浏览器均需可信操作者配置，不在生成过程中联网下载。

工作资源另设上限：浏览器磁盘缓存128MiB、B-roll工作帧512MiB、压缩分块合计1GiB；超过则失败退款。CPU（处理器）时间、队列及外部服务费用沿用P0边界；这不是小内存生产服务器容量验收。没有部署、生产访问、额度变更或新增付费调用。

## P0里程碑记录：2026-10-23 本地候选

现有短片、Claude（内容与口播规划）及实景剪辑能力保留。`legacy` 默认预设继续支持 Codex（隔离规划器）6–60秒、Claude 6–180秒；`short` 显式预设最多60秒。旧请求不隐式更换引擎，默认参数的请求摘要保持兼容。此前“Claude未开放”和“全部视频最多60秒”的说明仅适用于下方注明日期的历史实验。

新增 `exec_pitch`（高管汇报长片模式）支持6–600秒，当前仅接受可信配置登记的因果稿、口播节拍、本地PCM（未压缩音频）和镜头素材。最多30个口播段落、240个镜头；八分钟及以上至少40个镜头。段落组织论证，一个段落可以拆成多个完整口播节拍，不以提高正文或段落上限替代镜头模型。

输入内容包 → 网关检查账户、来源与音频 → 原有任务冻结及重试 → Worker（执行进程）复查 → 单任务可信FFmpeg剪辑 → 复用本地配音与字幕 → 完整解码、时间轴、稿件、音轨和摘要复查 → 原子发布 → 原有独立结算。网页真实创作表单和 MCP（模型工具协议）入口均传递预设及内容包编号。登记目录未配置时，能力接口明确显示长片未启用。

时间轴使用24帧每秒；每个音频为48000采样每秒、单声道16位PCM。镜头长度由实测样本数向上取整到帧，再加明确的声音前后留量，各6–12帧；取整余量小于一帧。镜头连续、无重叠、无空隙，且合计必须等于所选时长。不能容纳自然口播或画面不够长时失败；不加速、不截断、不均分时长、不循环或冻结画面。此阶段是**节拍同步**，不是逐字对齐。

独立交付校验还会解码最终AAC（压缩音轨），逐镜在预期样本位置与登记PCM的高能量窗口比较；归一化波形相关度低于0.90即拒绝，捕捉换错声音或节拍错位。该检查需要保留可信登记包供结算及再次下载时复核；它检验音频复用与节拍位置，不判断口播读音、文本语义或逐字同步。故意把音轨延迟半秒的负例必须失败。

资源上限：沿用单个渲染租约；长片队列最多等待15分钟；渲染最多时长的12倍、字幕最多8倍、独立可终止的交付检查最多4倍；网关传输最长6小时，长片空闲读取上限60秒，排队、编码、字幕和检查每10秒以内更新进度。素材合计最多256MB，每段音频最多2MB、画面最多32MB，输入JSON最多128KiB。长片只有本地输入路径，不运行内容中的指令，不开放模型代码、任意路径、下载或付费服务。

成本与计费：新路径外部规划、配音及素材服务调用为零，`total_cost_usd=0`仅代表外部服务商费用，本地计算未计价。继续沿用既有80点冻结、至少70%结算及失败全退规则；没有修改生产定价、全局预算或账户限额，也没有证明这些点数覆盖长片计算成本。长片默认未启用，需要操作者完成本地输入登记和容量评估。

长片输入格式、真实请求及复现入口见 [内容制作说明](VIDEO_AUTHORING.md#p0-长片登记与复现)。自动文件校验通过仍保留 `content_status=NOT_REVIEWED`（待人工审阅）。本节记录P0长片草稿能力；浏览器分块动画已在P1接入，P2素材入口也已实现，但真实客户素材验收未完成。P3新增可选更严混音和双语工程，真实韩语与人工选声待完成；逐字同步及独立画面/客户规则门槛未执行。历史P0内容包沿用-17至-15 LUFS（综合响度）、真峰值不高于-1.5的旧声音门槛，不改称P3达标。

相关实现：`gateway/exec_pitch_contract.py`、`exec_pitch_inputs.py`、`exec_pitch_delivery.py`，`worker/exec_pitch_renderer.py`、`video_qa.py`，由现有 `mcp_server.py`、`video_generation.py`、`video_renderer.py` 调用。没有替换现有实景或短片管线，也没有发布、部署或访问生产。

## 输入到交付

完整原文 + 客户品牌模板 + 6–60 秒 + 横/竖画幅 → 隔离 Codex 读取 `source-motion-video` 技能，仅写严格分镜 JSON → 网关和 worker 分别核验原文引用、数字、重复内容、时长与版式 → 可信 Pillow/FFmpeg 渲染 → 离线 MeloTTS 中文配音 → 按旁白时长生成 VTT → H.264/AAC MP4、海报和字幕验收 → 原子发布后结算。

PPT 和视频分别有 job_id。网页“PPT＋视频”创建两个独立任务，不用一个大任务掩盖部分失败；每项单独冻结、完成、退款和重试。已完成的另一项保留。组合冻结总额为 60＋80 点，重试只冻结失败项。接口不接受 legacy composite 一体生成作为新版流程。

范围是**动态图文讲解**，不冒充电影级文生视频、真人数字人或产品录屏。模板提供配色，场景根据内容选标题、对比或流程；横竖版分别排版，不以一张模板复制全片。无原文证据的收益、数字和产品画面不得补造。引用存在不等于事实审核，交付 `content_status=NOT_REVIEWED`，仍需人核对论断、专有名词读音。

## 生产组件和扩展点

- `gateway/video_contract.py`：纯数据契约，两侧复核；`gateway/mcp_server.py`：异步任务、权限、独立结算与重试。
- `worker/video_generation.py`：隔离规划、单任务资源限额、可信渲染与配音调用；`worker/video_renderer.py`：受控版式、像素容量与 MP4 编码。
- `worker/video_speech.py`：固定离线模型，最长 1.2 倍语速；旁白装不下就失败，不截断，也不交付静音替代品。
- `gateway/delivery.py`：全帧解码、时长、720p/24fps、AAC、海报尺寸、逐场字幕匹配及不可变文件摘要；没有文件不能完成/结算。
- MCP（模型工具协议）新增 `create_video`、`retry_job`，沿用自己任务的 `get_job_status`、`get_job_artifacts` 与相同鉴权下载。
- **Claude 接口保留**：内部 `planner_provider=claude_cli` 与 Codex 使用同一分镜 schema。当前因其独立登录隔离未验收，明确拒绝，不假称可用、不静默转用 Codex。未来接入只替换规划器；后续渲染、配音、文件验收、计费仍共享。公网 capability 如实返回 `claude_cli: false`。

## 从试用纳入的制作规则

1. 一场讲一个意思，流程/对比使用对应版式；品牌色一致不等于布局重复。
2. 先校验分镜和文字容量，再编码；时间轴由场景和旁白的实际时长闭合。
3. 生成型视频用已校对的旁白稿制作字幕。ASR（语音转写）只辅助检查，不反向覆盖原文。
4. 字幕、音频、文件验证必须由本平台控制，第三方“完成”或自检日志不代表可交付。
5. 接入新的画面或配音供应商时，必须有明确输入输出、原文约束、权限隔离、成本、取消、错误及真实样片，不能只安装 SKILL.md 就列为生产能力。

实验文件：`evz-trial/video.mp4`；`holland-delivery/`；MeloTTS 单独样音 `melo-test.wav`。语音模型官方来源：[sherpa-onnx 中英文模型](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html)，模型包包含 MyShell.ai MIT LICENSE，安装脚本锁定摘要。
