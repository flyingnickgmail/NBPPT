# 中文汇报／产品讲解视频制作体系

> **当前入口与能力范围**以 [当前视频能力](VIDEO_CAPABILITIES.md) 为准。本页的早期 6–60 秒、Claude 尚未开放、旧测试数量等说明保留为历史记录；不能用于判断后续 P0–P6 开发目录或线上服务器的状态。

## 字幕、原生竖屏与可选音色（本地候选，尚未部署）

2026-10-18 接入：完整原文 → 原有隔离分镜规划 → 按 16:9 / 9:16 原生排版 → 所选离线音色（或显式静音）→ 根据实际旁白时长烧录中文字幕 → 原有独立文件验收和结算。继续保留 Claude 分镜提供方接口，当前未验证时仍明确拒绝。

- `worker/video_subtitles.py` 是平台自己的可信字幕后处理器。采用 OpenCreator 试验确认的字幕/音频/合成分阶段方法，不引入其桌面服务、翻译调用或缓存执行器。仅使用已通过分镜契约检查的本地 VTT；原始字幕供验收和下载，烧录副本按画幅分为最多两行，容量不足明确失败。
- 竖屏标题、对比卡片和流程按 720×1280 重新排列，不缩小横屏加黑边。画面底部保留字幕安全带；文字不以省略号掩盖超限。
- 默认音色保持 MeloTTS。`video_voice=melo|kokoro_female|kokoro_male`、`video_narration`、`video_subtitles` 贯通 REST、MCP 和网页。Kokoro 是可选的本地模型，不是云配音接口；未启用时在冻结算力前拒绝。失败不回退其他音色或静音。
- 新选项参与请求身份校验，默认参数兼容旧版请求摘要；重试原样保留音色和字幕设置。规划器仅可写独立 planner 子目录，宿主渲染与发布目录不向规划器开放。新任务目录和每次独立字幕临时目录防止旧片缓存复用；失败保留原输入，禁止无产物完成。显式要求的配音音色及字幕状态需通过交付校验。
- 烧录前检查 FFmpeg 的 subtitles/libass 滤镜；实际生成后比较音视频流和时长，完整解码并验收文件摘要。仅检查二进制存在或工具返回成功不足以交付。所有 subprocess 使用参数数组，不接收用户文件路径或滤镜表达式。

部署准备：保留现有离线运行时；可选运行 `bash deploy/production/install-kokoro-model.sh /opt/nbppt-video-runtime` 安装锁定摘要的 Kokoro v1.1 中文模型，保留 Apache-2.0 许可。worker 配置 `NBPPT_KOKORO_MODEL_DIR`；完成服务器真实音色与资源测试后才在 gateway 设置 `NBPPT_KOKORO_ENABLED=true`。生产 FFmpeg 必须有 libass，必要时通过可信环境变量 `NBPPT_FFMPEG` 指定完整二进制路径。用户请求不能安装模型或选择执行文件。

本地验证：158 项 Python 全套测试、14 项前端交互测试通过；最终字幕位置调整后另跑字幕与真实媒体集成回归。真实 Codex 生成 30 秒四场景分镜并完成横屏；同一分镜用于横屏/竖屏及三音色对比。集成回归实际运行渲染、配音、字幕、QA、失败退款、新任务重试、结算及鉴权/Range 下载，只有规划器在该回归中使用固定计划。可选音色测试使用真实模型，没有用模拟波形冒充音质。

Linux 候选验收：158 项测试通过；服务账号真实任务 `video_ee6552c244` 完成 30 秒竖屏、Kokoro 女声与中文字幕。服务峰值内存 1,105,063,936 字节（约 1.03 GiB），无 OOM 或重启；下载摘要、Range 206、未登录 401、普通密钥管理接口 403 均通过，失败退款/新任务重试由真实媒体集成测试覆盖。生产发布后的在线复测仍是独立验收。

范围限制：自然度与专有名词仍需人工听审，视频内容仍标记 `NOT_REVIEWED`。本机通过不等于服务器发布验收通过。样片采用动态图文，不是影视级生成视频。

## 输入到交付

完整原文 + 客户品牌模板 + 6–60 秒 + 横/竖画幅 → 隔离 Codex 读取 `source-motion-video` 技能，仅写严格分镜 JSON → 网关和 worker 分别核验原文引用、数字、重复内容、时长与版式 → 可信 Pillow/FFmpeg 渲染 → 离线 MeloTTS 中文配音 → 按旁白时长生成 VTT → H.264/AAC MP4、海报和字幕验收 → 原子发布后结算。

PPT 和视频分别有 job_id。网页“PPT＋视频”创建两个独立任务，不用一个大任务掩盖部分失败；每项单独冻结、完成、退款和重试。已完成的另一项保留。组合冻结总额为 60＋80 点，重试只冻结失败项。接口不接受 legacy composite 一体生成作为新版流程。

范围是**动态图文讲解**，不冒充电影级文生视频、真人数字人或产品录屏。模板提供配色，场景根据内容选标题、对比或流程；横竖版分别排版，不以一张模板复制全片。无原文证据的收益、数字和产品画面不得补造。引用存在不等于事实审核，交付 `content_status=NOT_REVIEWED`，仍需人核对论断、专有名词读音。

## 生产组件和扩展点

- `gateway/video_contract.py`：纯数据契约，两侧复核；`gateway/mcp_server.py`：异步任务、权限、独立结算与重试。
- `worker/video_generation.py`：隔离规划、单任务资源限额、可信渲染与配音调用；`worker/video_renderer.py`：受控版式、像素容量与 MP4 编码。
- `worker/video_speech.py`：固定离线模型，最长 1.2 倍语速；旁白装不下就失败，不截断，也不交付静音替代品。
- `gateway/delivery.py`：全帧解码、时长、720p/24fps、AAC、海报尺寸、逐场字幕匹配及不可变文件摘要；没有文件不能完成/结算。
- MCP（模型工具协议）新增 `create_video`、`retry_job`，沿用自己任务的 `get_job_status`、`get_job_artifacts` 与相同鉴权下载。
- **Claude 接口保留**：内部 `planner_provider=claude_cli` 与 Codex 使用同一分镜 schema。当前因其独立登录隔离未验收，明确拒绝，不假称可用、不静默转用 Codex。未来接入只替换规划器；后续渲染、配音、文件验收、计费仍共享。公网 capability 如实返回 `claude_cli: false`。

运行时安装/环境变量及候选发布步骤见 [生产部署](../deploy/production/README.md)。生产不执行客户提供的渲染代码、第三方安装脚本或文件路径；模型和渲染代码只读归 root。2GB VPS 上视频全阶段与现有账号信号量串行，双轨进度不表示模型并发。

## 从试用纳入的制作规则

1. 一场讲一个意思，流程/对比使用对应版式；品牌色一致不等于布局重复。
2. 先校验分镜和文字容量，再编码；时间轴由场景和旁白的实际时长闭合。
3. 生成型视频用已校对的旁白稿制作字幕。ASR（语音转写）只辅助检查，不反向覆盖原文。
4. 字幕、音频、文件验证必须由本平台控制，第三方“完成”或自检日志不代表可交付。
5. 接入新的画面或配音供应商时，必须有明确输入输出、原文约束、权限隔离、成本、取消、错误及真实样片，不能只安装 SKILL.md 就列为生产能力。

实验文件：`evz-trial/video.mp4`；`holland-delivery/`；MeloTTS 单独样音 `melo-test.wav`。语音模型官方来源：[sherpa-onnx 中英文模型](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html)，模型包包含 MyShell.ai MIT LICENSE，安装脚本锁定摘要。
