# P6 来源约束的叙事打磨

既有原文、因果稿和中文干声 → 先写“问题—机制—来源支持的证据—收束”简报 → 把原有口播节拍对应到可见动作 → 可信HTML模板按原时钟渲染完整片 → 独立文件、声音、同步、最终帧和客户规则检查。用户要求复用配音，因此本轮保留原来已经分段的20段录音及其顺序、留量和时长，先重写因果论证，再重新编排画面动作，不声称重新创作了口播。

## 本材料的叙事选择

贯穿对象为同一个待出库包裹，问题为“包裹不在原库位，下一步凭什么判断？”：

| 段落 | 镜头 | 叙事作用 |
| --- | --- | --- |
| 问题 | 1–3 | 原库位没看到包裹，空货位不能直接判定丢失，引出下一步如何查证 |
| 查证机制 | 4–14 | 汇集来源记录，先查交接再核实同一标签；仍对不上时交接已知与未知，由责任人核查；现场确认后更正记录、保留旧记录并通知，接手人继续核对 |
| 来源支持的证据及边界 | 15–17 | 来源支持功能机制；处理记录可供后续复盘，但本片没有观察到的客户成效，单次演示不能证明效率或收益 |
| 试点收束 | 18–20 | 建议小范围试点，明确谁核对、谁确认、谁接收通知，凭后续异常记录决定是否扩大；回扣可追溯判断 |

这份原文材料只提供产品功能与情境演绎设定，没有实测客户成效。因此 `observed_outcomes=[]`，机制演绎、建议验证和限制条款分别标记，不能把“来源有这句话”当作业务效果已得到证明。完整原文引用保存在简报和逐镜来源记录中。

## 受控契约与来源

可选 `story` 只接受纯数据：版本、原文/同账户父输入/完整声音身份摘要、单一问题、贯穿对象、四段连续论证、条件判断、证据边界、回应同一问题的试点建议和有限动作枚举。声音身份绑定每镜原口播、音频摘要、实测样本数和前后留量。

登记时独立读取同账户父输入、核对内容摘要，并比较完整声音身份，防止同时改稿改声后只重算自身摘要。父输入仅用作历史声音/稿件身份依据，不携带绿色QA或客户审批，也不要求改写父版本缓存。原PCM、实测字词、字幕、节拍、响度、峰值门槛均沿用。

`tools/exec_pitch_story.py` 是针对这份已知20段仓库稿的人工编排示例，先构造因果简报再赋予新镜头动作；不承诺任意行业自动生成同等叙事。`gateway/exec_pitch_story.py` 检查连续阶段、原文引用、声音身份、条件交接在确认之前、证据分类和试点未部署状态，不认证故事的审美或事实真实性。

目前P6新画面仅明确支持16:9中文P4管线。其他旧模板、竖屏、短片、实景和既有规划路径保留；不会静默将新模板降级成其他画幅或改时钟。

## 画面实现与检查

`worker/html_motion/story_scene.js` 是固定、离线的可信模板，用同一包裹图形、货位、来源记录、角色和交接动作贯穿全片。更正的是库位记录，不画成系统自动移动实物。未知项不会自动变成已确认，通知不等于完成。证据段不生成业绩图、虚构客户记录或产品界面，片尾是有边界的建议。

没有客户端HTML/JavaScript、路径、网络素材、远程字体、客户假界面或品牌猜测；全部文字经原有纯文本和数字限制，客户规则同时扫描新增画面文字。浏览器沙箱、网络禁止、确定性回跳、96帧分块、资源闸门和取消流程保留。

新增先行 `story_brief.md` 与 `story_evidence.json`，绑定阶段/镜头/原文/声音和24帧时钟；交付独立复算这两份文件和来源清单，改动即拒绝。`STORY_INTEGRITY` 只表示来源/声音/时钟契约通过，`human_story_review=NOT_REVIEWED`，不代表人类内容或客户审批。

本轮是完整叙事修订，移除新输入中的P5单镜 `revision` 声明，不冒充只改一镜。原P5输入/视频保留，P6全片新渲染，不复用旧绿色QA；引擎指纹变化使旧画面缓存失效，这是既有缓存安全规则，不修改旧缓存摘要来强行复用。P5单镜路径仍通过当前依赖重新登记的缓存回归验证。
