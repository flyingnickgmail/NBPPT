# P5 客户规则、最终画面审核和有限修订

已登记原稿、中文声音、旧版本与本地规则 → 校验账户、原文、版本链和渲染依赖 → 单镜修改、复用未变分块 → 重新混音、烧录字幕并完整独立质检 → 请求绑定最终成片的审核。规则或授权不齐仍阻断，旧片和音轨保留。仅明确的 `exec_pitch` 输入启用这些字段，旧短片/P3契约不变。

## 信任与审批

`NBPPT_EXEC_REVIEW_ROOT` 是管理员控制的绝对目录，不能让客户端、模型、上传服务或规划器写入。默认未配置；没有后台审批接口。规则/回执按账户与内容摘要隔离，文件不可覆盖。`authority.json` 由管理员实际授予 `rule_reviewers`、`final_visual_reviewers` 名单；工具不会自动授予自己或生成审核人。

该信任来自管理员目录权限、审核人名单和原始依据登记；当前没有外部数字签名或独立身份认证服务，不能单靠一个名字/文件摘要证明某个人真实作出过批准。部署前必须由真实管理员保护该目录并核实批准来源，本轮没有执行部署或创建真实审核人权限。

`governance.profile_sha256` 指向该目录下 `<owner>/profiles/<sha256>.json`。规则有客户编号、连续版本及父摘要、原文摘要、审核人、创建/到期时间、授权依据摘要、品牌、禁用/必需用语、内外披露范围、IP脱敏、是否必须已审产品素材和原文数字策略。`candidate` 是候选，永不成为通过；`test_fixture` 只能用于合成测试卡，不能作为实际客户许可。真正的 `human_record` 要有管理员授予的规则审核人和原始依据文件。

文字检查只读取实际画面标题/标签和口播，不扫描作为政策元数据的禁用词本身。未脱敏IPv4、禁用词或缺必需用语拒绝；全部数字仍受既有“原文实际数字”契约约束。披露、品牌、商标、水印和画面中的敏感信息仍需要最终画面的真实专项审核，文字干净不会自动推断品牌/OCR或脱敏通过。自动IPv6/图像OCR/商标识别尚未实现，不能据此宣称已覆盖。

最终QA产生 `final_review_request.json`，仅为审核请求。真实回执必须绑定账户、原文、输入版本、客户规则摘要、最终MP4摘要和全部切点/镜内取样帧记录摘要，并覆盖品牌、水印、禁用词、披露、脱敏五个范围。证据文件也按摘要保存；过期、换片、换规则、换输入、换帧、未授权审核人、缺证据都会失效。`content_status=NOT_REVIEWED` 继续保留；画面专项批准不是内容或韩语译审批准。

登记已有记录（不会生成批准）：

```sh
python tools/exec_pitch_review.py --store <管理员审核绝对目录> \
  --kind profiles --record <实际客户规则.json> --proof <真实批准依据文件>
python tools/exec_pitch_review.py --store <管理员审核绝对目录> \
  --kind receipts --record <最终画面实际审核.json> --proof <真实审核依据文件>
```

最终索引不覆盖既有决定；修正规则/画面需生成新版本及新审核。当前没有在线审核撤销/角色管理界面，也不自动恢复原已失败任务或补记完成事件。收到批准后必须通过原任务/重试入口重新执行同一输入与最终检查；只有新片的实际摘要完全一致才可能复用该审核，普通发布/结算流程仍独立复检。

## 局部修订

`NBPPT_EXEC_REVISION_ROOT` 也是管理员目录，只保存重新通过独立文件和帧检查的父版本原始画面分块、首尾PNG及清单；不缓存绿色QA、审批或结算状态。缺客户批准的待审片可以提供机械校验通过的原始画面，不能提供交付资格。

输入 `revision` 明确绑定 `parent_input_id`、`parent_job_id`、`manifest_sha256`、`shot_num` 和一个操作：`replace_opening` 只改第一镜画面；`polish_shot` 只改一镜画面；`swap_vo` 只替换一镜已经登记的本地PCM/实测样本数和留量。三者都不调用合成或规划，不允许改口播稿、其他镜头或全局声音配置。声音时长改变造成后续时钟变化时，后续镜头的缓存自然失效；总时长门槛不放宽。真正的配音替换仍需新的声音对齐证据，本轮只实际运行了开场画面替换。

复用键包含账户、原文、原始画面/音频摘要、口播、镜头数据、时钟、画幅、产品素材范围、声音及混音配置、语言、引擎源码、浏览器/字体/Lottie/FFmpeg版本。已登记PCM的内容摘要固定其原声音/合成速率，不根据文件名推测服务商；本轮B版身份另由既有选择与声音缓存记录核对。引擎依赖改变后缓存拒绝继续复用。

每个复用分块和PNG均重新验摘要；时间轴仍连续、24帧、96帧分块，浏览器仍独立离线且保留沙箱。新片重新拼接、原声音混音和字幕烧录；完整解码、旧节拍≥0.90、逐字延迟≤2帧/相关度≥0.80、响度−17至−15LUFS、真峰值≤−3.8dBTP、最终全帧与切点检查全部重新执行。`revision.json` 记录哪些镜头/音频实际复用、哪些重渲以及 `qa_reused=false`，独立检查重算复用身份。

## P4 时间待审收尾

保留80毫秒格点原始模型输出。对第6/8/10/18镜用固定40毫秒前置静音重新推理，将模型时间坐标减回原录音；另外用80/120毫秒前缀复核稳定性。只用于模型分析，最终播放仍是原始干声，绝不加静音到成片或变速。固定采用40毫秒结果，不在多次结果中择优拼字或平均插值。

版本2对齐证据绑定原始版本1、全部12次复核、各分析WAV摘要和真实PCM。校验前缀必须为指定静音且后续字节完全等于原录音，原文逐字相同、时钟仍为80毫秒量化后的坐标变换，固定结果不能零长或重叠；多组估计差异/相对原边界超过80毫秒仍拒绝。此举解决模型区间塌缩，不能证明音素绝对精度或真实人工听审，不能代替独立语音识别正确性验证。

## 本机复现与当前缺口

使用原NBPPT虚拟环境，现有MLX环境只做离线对齐；无安装、模型下载或新配音。

```sh
python tools/exec_pitch_p5_acceptance.py --root <全新本地目录> \
  --registration workspace/exec-pitch-p4-20261023/registered/registration.json \
  --parent-job <P4完整任务绝对目录> \
  --runtime workspace/exec-pitch-p3-20261023/runtime-env.json \
  --probes workspace/exec-pitch-p5-20261023/alignment-rechecks.json \
  --version video_v12_review_only
```

当前真实客户规则/客户素材/品牌授权和韩语译审未提供，只登记明确的候选。当前样片仍为本地待审，普通合格产物下载及完成结算继续阻断并退还冻结点数。合成测试的批准闭环仅证明机制，不作为客户审批证据。没有推送、部署、外部模型调用、付费调用或委派。
