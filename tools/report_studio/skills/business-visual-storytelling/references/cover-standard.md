# 友车科技内容分享图规范 · 3.2

输入为有来源的报告，输出为一张可独立阅读的内容图片；网页右上角是它的缩略入口。保持认可版本的暖纸、铜橙、精细编辑插画与留白。规范固定证据、层级和阅读要求，模型根据材料决定主体与构图。

选图前执行 [question-policy.md](question-policy.md) 的业务审题；数值和引文正确不代表问题有价值或行动成立。审题结果须影响标题、主图和受众建议，不能只在脚注承认正常业务基线。

内容关系和出版构图分开选择。condition_contrast并不意味着两根横条：只有模型明确选择presentation.rendering=exact_reference且简单范围比较就足够时，才使用精确参照图稿。其余定性关系可用编辑插画，真实数量仍由数值引擎绘制。模型从批准锚点选择对象、条件与行动，不生成数量刻度或虚构企业点位。交集、流程和真实数量比较不可硬套。

## 3.2 · 从文档摘要转为可分享的图形论证

presentation单独设计阅读层次。先确定一个占据一半以上画面的连续主视觉，再为必要旁注找到贴近所解释部位的位置；不是先排齐段落，再找空白补图。三种出版构图均按材料选择：annotated_hero是一幅带直接注释的主体；hero_with_inset用大主体解释待判断情景，小参照保留正常基线，两者明确为分析情景而非先后演变；paired_scenes只用于同位对照确有必要时。不要所有主题用同一个物件、切面或溢出造型。

标题、一个导语、主视觉、短旁注、受众启发、边界及来源形成主次。lead_copy在subtitle与thesis中只选一句上图，另一句独有的必要信息必须被可见内容完整覆盖。所有panel必须安排唯一可见位置，禁止把重要业务解释删成脚注。避免重复印题、重复结论、连续的通栏分隔线、字段标题和性质按钮。性质仍清晰标注为披露、来源建议、待验证或分析建议；建议落点与图中的实际条件相邻。

主图优先表现同一对象的状态、包含或超出、结构作用。精细线描、剖切、纸面层次或雕版感可以增加辨识度，前提是每个主要部件参与解释。没有实测数量时，轮廓、物件数量、透视和面积都只是示意，禁止添加刻度、比例、分项数量与精确阈值。不能用无量纲的立柱/横条冒充数据图，也不能拿一个复杂装饰物替代简单但准确的关系。

复核同时看信息是否准确和是否真的成为图：若图只有两根条、多个等宽正文框或通篇段落，主体关系没有占据视觉中心，须重新设计。不能以抄全全部文案作为可读性通过依据。采用主图加小参照时，不误画成已发生的前后变化；范围内必须真正被包含，超出必须在参照外可见，参考边界必须命名。若原构图失败，重新选择presentation和图形解释，不继续给旧条形换材质。

不要把没有对象识别度的不规则团块、等高线或抽象花边当作新颖。重新设计时保留报告题名和锚点所在原文，让模型知道“库存”“任务”“权限”具体指什么。材料有可辨识对象时，优先让其真实外形或业务状态承担说明；可用精细俯视、剖面或剪影，但不是道具陈列。重复物件只能作为明确标注的概念纹理，不能让其数量、面积或位置被读作实测样本、比例或地理分布。材料没有实体依据时可以使用直接关系图，不能硬造物件。

参照边界表示的是命名的业务条件，不能画成仓库、容器等物理容量从而偷换判断标准。概念情景不得偷偷具名为实际公司/国家。正常情景的对象应完全位于参照内；超出情景只有实际越界部分使用强调色，不能留一圈未解释的越界。大小图不得暗示库存增长过程；标题与参照说明共同保留分析情景性质。

图形论证描述业务需要的最小可见关系，不增加没有材料依据的几何等式。对象在适用范围内不等于对象外缘必须与参照分毫不差地重合。直接可辨认的对象与一条具名参照，已能表达包含及越界时，不额外强制第二条库存轮廓或双线叠印。复核核对实际对象是否处于范围内/外，以及颜色、标签和行动是否对应；不以缺少无业务意义的辅助线否定正确关系。任何这种修订仍须锁定文案和证据，再对实际图片独立复核，不能为了接受成图改变业务条件。

## 内容与表达的对应

先从材料比较三个值得回答的问题，选一个核心判断和两三条必要支撑。比较三种不同的信息结构，说明选择理由、误读风险；不要只给同一物件换材质。

| 材料要解释的内容 | 可选择的主视觉 | 必须看得见的关系 |
|---|---|---|
| 两个状态为什么不同 | 同视角、同位置的对照插画 | 只改变相关部件/条件，变化处直接标注 |
| 一个系统里什么承担作用 | 带注释的剖面或局部放大 | 对象、部位、功能一一对应；结构有材料依据 |
| 资源、成本、规模差距 | 一个主数据图＋短旁注 | 数值、同尺度、期间、单位、估计性质完整 |
| 权限、范围、共同条件 | 命名的包含/交集或条件对照 | 允许范围、排除位置、必要条件直观且准确 |
| 布局或位置决定结果 | 定位图或空间对照 | 位置真有解释作用；示意位置不冒充精确地图 |
| 变化发生在哪里 | 同位时间切片/前后差异 | 真实时点与改变的对象；规划区别于发生 |

这是候选语法，不是六套固定素材。可用精细线描、局部剖切、灰阶雕版感和轻微层次；实体只有承担结构、部位或状态解释时进入主图。金融或权限主题没有实体依据时，使用准确的关系图，不强造建筑或道具。

网页输出字段要区分图种与关系：visual_grammar 中结构解释用 annotated_structure，同位状态对照用 action_contrast，范围用 scope_map，条件组合用 condition_contrast，职责用 role_composition，证据分类用 evidence_landscape，数量用 quantitative_comparison，时序用 temporal_change。containment/intersection 等只是 visual_proof.relation 的关系值，不能填进 visual_grammar。

## 图形论证

提取2—5个材料锚点，给出连续原文和所属章节。直接命名对象/动作/条件/结果，不让读者猜图标。visual_proof说明：什么可见形态表达什么关系，材料改变后哪个图面部分必须改变。无数据的面积、数量、透视比例均注明概念示意。

剖面/结构图可选 annotated_structure（注释式结构图），使用 comparison/containment/conditional 等已有关系说明其证据；部件位置不代表测量比例。普通主题场景 material_scene 不能独立成为解释。每个主要部件都应被短标签与本图论点使用，只有气氛作用的部分退为辅助。

**不使用人物摆拍、人物手势、机器人代称、流程框图、串联方框、软件架构图或代码截图。** 条件对照和集合图可以用，但不能每次默认套用；所有行结论相同时合并，而不是造差异凑图。静态构图也应解释关系，不能靠动画补救。具名观察的时间对齐不等于软件流程泳道；若材料讲的是记录晚于事件，允许用同一事件的先后位置直接解释时滞，须标明机制示意、无实际日期与时长，不画成已测得的经营过程。

## 版式与文本

固定语气是研究图解，不是广告。标题12—22字、最多24字两行；主判断最多42字。主视觉约占一半以上；旁注贴近对应对象，给受众的具体启发置于独立且简洁的落点。不强制三段等高，不用四个摘要卡片冒充全景图。

最多3项核心数值，逐字保留约/超过、负号、单位和期间。最多5个主图短标签，每个14字以内；2—3条支撑判断，每条38字以内，最多4条，短标题10字以内。内容超量先删次要信息，不缩字。

性质标记：observed=披露，proposal=来源建议，inference=分析建议，unknown=待验证。对友车科技的启发说明应关注或验证什么，不能冒充已经取得的成果。来源建议和本报告分析分别署明。

来源区给机构、材料简称和完整披露日期，必要边界最多80字。品牌“友车科技 · 研究图解”和“AI辅助图解 · 依据输入报告整理”各一次。不得用来源发布日期代替统计期。

## 输出规格与检查

- 暖纸白 #F5F1E9、石墨黑 #252824、铜橙 #B45F36；墨线与留白优先，质感放在不会干扰阅读的地方，避免满页粗框和大面积橙色。
- 分享主稿优先竖版4:5。1600像素宽时安全边距约96、标题约88、正文约48、来源至少32；比例是设计基准，检查实际生成尺寸。不能把“请求高分辨率”当作已输出高分辨率。
- 缩略入口只要求标题、主体关系、主要判断清楚；放大后支持完整阅读。375像素宽模拟检查不等于真实手机或社交软件压缩实测。
- 图表数字密集时优先确定性图形和排版；当模型选择 quantitative_comparison 且2—3项事实来自同一 qualified_dot 图、统计口径足够简洁时，网页使用精确数值图稿引擎：中文排版与坐标从同一原值直接绘制为1600×2000 PNG，保留模型标题、结论与受众启发，不使用生图像素。其余语法继续生图并逐项核对可见数值/汉字/限定。不得让图片模型自由估画等距刻度；无法核验比例时改用精确图稿或保留文字比较。
- 设计复核检查“问题—图形—证据”，图像复核描述实际可见关系。禁止仅以文字正确或画面漂亮通过。事实错、条件反转、边界省略、字体糊或重叠均返修；模型复核是辅助，交付前仍看成图。
- 保留现有逐字引文、版本绑定和下载校验；换规范后旧图不自动冒充新生成。重新生成只有通过当前规范才可复用。

## 2.9 · 分享图的第一眼与阅读顺序

数量比较明确选择 reader_design.numeric_layout：2—3个非负值、短类别、需要突出规模差异时用 paired_columns（并置的大比例立柱）；含负值、长标签或多个排序对象用 horizontal_scale（共同水平标尺）。两者均保持零点、同尺度、真实限定，不将独立同比数据连成时间线，不填“差额面积”暗示库存。paired_columns 的柱顶遇到大于/小于值时用开放边界和界限符号，不补造终值。

数量型分享图不是论文页：只保留一条主判断，主图占据最大连续空间，数字约为正文的3倍；数字、对象标签和几何位置必须相邻。图已表达的事实不再另写一行复述。panels优先两条：一条必要解释、一条受众具体启发；总支撑正文优先60字以内。正文不能排成三行等大的字段表，也不把长统计口径放到主标题和图形之间。期间和单位紧邻主图；分母差异、估计说明和来源在底部完整保留。

主图只负责揭示比较，不预设原因。启发为独立的短收束，明确“分析建议”；在300像素宽缩略图上，读者仍应看懂标题、两个对象与大小关系；完整原图应读得清口径与来源。不能为了尺寸达标把原32像素来源缩成23像素。验收时分别检查缩略图和原图，不用模型自评替代。

paired_columns必须填写reader_design.chart_caption，55字以内，直接印在主图上：统计期间、比较口径、单位，不写设计指令；以一行可读短句呈现。模型决定该布局是否合适，负数仍用水平标尺。该布局只显示thesis、真实数据和implication对应的一条启发；其他panel的必要信息须已包含在thesis或boundary，不得新增独立论点后寄希望于引擎自动显示。title/subtitle不重复同一句，主体位置已能说明的大小关系无需第三次复述。

## 3.0 · 信号与业务解释的组合图

先判断读者的问题：只是比较大小，可用单一数量图；如果要解释“为什么指标好看却不能证明业务结果”，优先 evidence_composite（证据与业务解释组合）。数量信号只是入口，不得再用两根放大的柱子或两条长线占满主图。

该语法的composition_parts必须含signal、explanation、implication三项，分别声明visible_relation（哪些可见关系帮助理解）、anchor_labels和panel_indices。它们是内容角色，不是三个方框或三段流程。每项引用真实锚点与批准文案，全部panels必须有实际画面位置；至少两条visual_proof分别核对数据信号和业务解释。模型选择一个连续的主构图，用邻接、对照、切面、局部放大或观察边界把三个角色组合起来；不要排成三张卡片。

优先从原文找“指标测量对象与读者误以为的对象有什么区别”。统计记录、物理状态和最终业务结果应分开命名；每种解释标明已披露机制、可能解释或待核对状态。可用有注释的编辑插画直接表现实际业务状态：物件只有在位置/状态/部位解释材料时出现，不是行业道具。不用人物摆拍、流程框图、无名圆弧、巨大的不等号加两句文字来代替解释；也不能把所有问题都画成在途车辆。

数值读数紧邻真实统计对象，仅作为小型证据标记。主画面应让人看到“哪些现象可能造成差别，以及哪些结论还不能下”。没有分项数量时，不画漏斗、桑基、份额饼或按面积分配三种原因；所有物件数量、区域大小注明示意、不代表数量或穷尽分类。未观测的状态不能画成已确认的去向；不得把不同分母的增长率当同批对象的转化率。

对受众的启发必须具体到要核对的业务证据，不止“加强管理”“关注风险”。分析建议独立署名。必要状态与解释可用短标签贴在相关位置，但须来自panels、visual_labels等批准展示字段；制作说明不得上图。

审核必须拒绝以下退化：只有数字大小关系，解释留在图外或小字脚注；三个等大的文档卡片；把可能原因画成已测得分类；把统计口径画成车辆物理流转；用任意数量的物件暗示未披露比例。逐项检查composition_parts是否实际可见，并确认图片独立阅读时能说清指标与业务结果之间的区别。

组合图至少有三条有依据的panels：signal对应数据信号；explanation至少引用一条独立于signal和implication的业务解释；implication对应分析建议。三种内容必须都实际绘入图片，尤其不能让“独立业务解释”只存在于规划JSON。读者应从具名的观察位置或状态看懂解释，不靠补读小字。

### 机制可见，而非原因标签可见

如果explanation只是“在一个范围内放两个带纹理的区域，各写一个原因”，即使是开放轮廓，也仍是标签整理，不能解释原因。拒绝仅靠虚线/排线区分未知而不表现具体业务状态的方案。说明每个原因怎样让“统计信号”和“业务结果”不一致：以材料支持的具体对象与状态差异作可识别的注释式编辑插画、局部剖面或同位对照。用对象的状态与观察边界解释机制，不能用区域名称代替机制。

模型仍自行选择贴题对象；汽车、运输、文件都不是一律禁用。当它们直接解释“运输尚未完成”“统计记录尚未同步”等已披露机制时可以使用精细线描，禁止玩具式主角、无关道具陈列和摆拍。不同候选必须比较是否让读者理解原因，不能一味回避真实对象而只剩抽象圈框。

### 组合图的编辑密度

内容角色不是章节目录：不印制大号1/2/3序号、通栏胶囊标题或橙色卡片头。正文和短标签直接贴近图中的状态；允许轻细引线，但不把并列解释连成流程。留白、大小、邻接和一处连续主视觉建立层次，不以边框建立层次。性质标记用小而清楚的文字，不做标签按钮。

一个业务机制只表现一次。主体已解释“业务已发生而统计尚未纳入”，收束就只保留一句具体核对建议，不再重画一套文件、电脑与记录。统计记录可用直接命名的记录位置或状态标记表示；不要把软件窗口、电脑屏幕、文档堆和表格截图当成专业感。来源和必要边界除外，禁止生图阶段自行增添批准文案以外的解释段落。

非确定性生图的复合信息图，数据信号默认使用相邻的准确读数和对象标签，不使用让图片模型估画的柱长或等距刻度。明确说明读数比较，大小与位置无定量含义；若需要定量几何，必须另由原值计算后验证，不能因为小图处于次要位置而放松比例检查。这样数据信号留下更多空间给机制解释，也避免数字正确、图形比例错误。

业务机制不能只剩两个大圆环、一边有点一边没点，或用任意缺口充当事件身份。匹配标记只作辅助；主关系应采用读者能理解的时间差、观察边界、部位作用或实际状态。若原文仅给定性时滞，可画明确标注的时间先后示意，用同一事件在业务发生与统计纳入两个观察中的错位解释延迟；不补造日期、天数、数量、阶段转化率，不把可能情形画成已发生的案例。模型根据材料选具体表达，不强制所有报告使用时间线。
