# 灵动报告实验室

v0.32 将分享图的内容关系与出版构图分开设计：模型选择主视觉、旁注位置和阅读顺序，避免条件对照自动退化为两根横条。保留所有证据旁注与限定，导语只呈现一条；定性编辑插画与精确参照图按用途分流。实际图文复核继续检查包含关系、条件方向和建议性质。

v0.31 在选图前增加业务审题：正常业务基线、证据性质、替代解释、缺失数据和可改变的决策。报告生成先形成结构化审题，分享图独立复核其标题与主图是否遵守判断边界；旧分享设计须重新审题。规则见 [审题规范](skills/business-visual-storytelling/references/question-policy.md)。模型审题仍需人工核阅，不能取代实际经营数据。

已有报告可用 `python -m tools.report_studio.cli reframe 输入.json --output 新目录 --feedback '具体编辑反馈'` 修订论点；只开放叙事字段，锁定原数值、引文和来源，清除过期分享图。网页完整生成和全景图入口均使用同一审题规则。

v0.27 将 [Business Visual Storytelling（商业研究的图形表达）](skills/business-visual-storytelling/SKILL.md) 接入正文生成、复审与全景图规划/生成/复核。按读者问题和数据条件选择图形；[18项配方目录](skills/business-visual-storytelling/references/catalog.json) 明确区分现有网页图种与需要扩展的高级图种，不把研究配方冒充已实现组件。

[内容图规范2.7](skills/business-visual-storytelling/references/cover-standard.md) 保留用户认可的 c8e7 版本暖纸铜橙与精细编辑插画。根据材料选择注释式结构、同位对照、范围关系或数据图，避免把全部主题压成同一种二维集合。人物摆拍、流程框图和无证据数量仍不接受。

正文新增三种定性表达：contrast按相同维度比较两个对象；membership用点阵表达有引文的类别归属；evidence_strip区分材料记载、建议和待验证。均不编造评分、比例或数轴，材料沉默不等于排除。生成和复审共享选图规则；图形替换会清除失效的旧读图与封面引用，再自动编排。

当前默认（v0.27）：长材料先形成有引文的报告，再由模型选择“对照、明确阶段或并列维度”的证据封面，避免强制行业物件。通用图表支持共享尺度、直接读数、随阅读展开、重播，以及减少动态/打印回退。旧三维报告仍可读取；需要三维设计时使用 `design --style spatial`。

一个可独立运行的交互报告生成工具，参考用户提供的两份 Kimi 灵动报告的表达方式，独立实现，不复制其代码或品牌素材。

输入文本或 Markdown → 模型按问题选图与复审 → 结构与数字引文检查 → 模型编排读图步骤 → 可交互网页 → 下载单文件 HTML 或内容 JSON。

可复用入口、输入约定、长材料内容复审与验收方法见 [能力说明](CAPABILITY.md)。下次换材料仍使用相同流程，不需要为每份报告另写网页。

## 启动

在 NB-PPT 仓库根目录执行：

```sh
.venv/bin/python -m tools.report_studio.app
```

访问 <http://127.0.0.1:8766>。使用现有 Python 依赖，无须安装前端依赖。默认只监听本机，不连接 PPT 网关、钱包、执行节点或生产服务。端口可用 `REPORT_PORT` 修改。

智能编排使用本机已经登录的 `codex exec`，消耗该账户现有额度。默认由 CLI 自己选择模型；结构化生成阶段使用中等推理预算，并另做受限内容复审，可通过 `REPORT_MODEL` 指定模型；不读取项目网关密钥。材料会被发送到 Codex 的模型服务。启动时使用 `--ignore-user-config`，因此不沿用用户配置中的插件、MCP 服务或自定义模型提供商；账户认证仍由 CLI 自己处理。使用临时目录、只读沙箱、禁用 shell 与多智能体，要求只返回结构化内容。初始生成最长 360 秒；如引文或数字检查失败，最多两次局部字段修复，完整流程共享 1800 秒上限。修复不能改正文、删图或修改未报错字段，之后重新检查；仍不通过就明确报错，绝不回退成演示结果。

不少于12000字符的长材料还执行一次内容复审，与生成共享1800秒预算。复审读取完整图表，可修改最多8处既有正文/要点、补3张互补图、替换12张有具体问题的图；不能修改来源、标题、封面指标或删除章节。新增与替换图重新核查引文，新正文不得增加材料外数值。工作台显示结果检查中的待核对项；这不等于自动事实核验。

也可不启动服务，直接调用同一能力：

```sh
.venv/bin/python -m tools.report_studio.cli generate 材料.md --output workspace/新报告
```

输出离线网页、结构化内容和检查结果，不覆盖已有目录。

## 可以使用的功能

- 输入 / 导入 TXT、Markdown；标题可自行修改。
- 智能整理叙事章节、关键指标、同单位比较图、趋势图、流程图；同一章节可以组合多张图。
- 同业矩阵支持列排序、主体行强调、逐格引文；方向明确且口径一致的指标可相对主体着色，异口径保留值但不参与优劣比较。未知值不作为零参与排序。
- 现状与目标图保留独立单位，区分“建议目标”与实际结果；未披露的现状不画零基线。
- 时间路线图支持工程泳道和紧凑时间线；稀疏路线默认紧凑，责任信息随事件保留。使用材料给定的时间列，全年未定窗口单列；规划与已记录事件分别标识，不推造未披露时长。
- 双变量散点图保留两个原始值与连续原文引文；支持零轴/实际样本中位数、区域含义、原值直标、标签避让、主体强调、阅读入场和重播。点保持等大，窄屏局部滚动并保留明细，不补造评分。
- 离线全球市场图使用陆地轮廓与等大国家概览节点，支持俄罗斯、巴西、泰国、澳大利亚、南非、中国；不表示精确厂址或跨口径销量大小。地图数据来源见 [底图说明](GEOGRAPHY.md)。
- 汽车主题提供原创整车轮廓、分层拆解、线框，以及可点击的车身指标图。
- 本地模式按标题和列表保留原文排版；不冒充智能分析，不自动生成数字图表。
- 三种封面动态结构、浅色与深色阅读、目录、阅读进度。
- 长报告在宽屏中提供随章节更新的上下文侧栏，保留本节图形类型、开篇摘录、来源入口和可点击关键指标；窄屏回归单栏。
- 点击图表和指标查看原文证据与绑定的来源、版本、日期；完整输入附在文末。
- 桌面 / 手机预览；下载离线单文件网页；保存 / 重新导入内容 JSON。
- 打印样式支持浏览器“存为 PDF”；不承诺与屏幕动效一致。

自带示例为虚构的星河汽车材料；示例是人工编写的展示数据，不是模型实测结果。真实模型实测证据另见 `VALIDATION.md`（如存在）。

## 当前边界

- 原型采用受控组件，避免任意模型代码执行；汽车图为结构示意，并非机械或品牌车型复原。模型设计的矢量场景仍受部件数量和几何规则限制，尚无任意三维建模；地图仅支持上述六国的经营材料，未知国家不会凭空定位。
- 数字检查只证明引句存在、对应数值出现；不能证明数据真实、单位正确、统计口径可比或正文全部可信。没有自动浏览、事实核查或业务验收。
- 原文最长 60,000 字、最多 24 章。超限报错，不静默截断；不支持 PDF、Word、图片识别。
- 单用户本机工具，无多人认证、持久任务、公共链接、团队协作或线上发布。关闭进程后生成服务停止；已下载网页继续可用。
- 刷新会清空输入；需要留存时点击“保存内容”。最近 20 份预览保存在本机进程内存，关闭服务后清除。工具不自动把材料写入仓库，Codex 自身仍可能有账户层面的日志与服务处理。

## v0.9：编辑设计、空间构图与按数据选图

长材料的 `generate` 已默认执行：正文与证据 → 内容复审 → 材料专属空间设计 → 数据形状选图 → 离线渲染。物体由模型按材料设计，渲染代码不包含美联储或汽车对象。`design.json` 保存每张图的选择理由与口径边界。


实际截图发现问题后，用同一能力反馈修正（保留原目录）：

```sh
.venv/bin/python -m tools.report_studio.cli design existing/report.json --output revised-report --feedback '具体的可观察问题，如主体遮挡或旁注夹杂制作说明'
```

- `editorial.css`：中文衬线阅读字体、暖纸白/石墨黑/铜橙、统一正文与图表网格；不依赖外部字体服务。
- `spatial_models.py` / `spatial_prompt.txt`：有界几何数据、真实材质、章节焦点和逐字引文。禁止模型输出可执行脚本。
- `space.js`：三维坐标投影、面片排序、曲面连续光照、材质细纹、整体/分层/线稿/展开演示，同步桌面侧栏与手机收起面板；暂停、离屏停止与系统减少动态。
- `chart_design.py` / `recipes.js`：按已有数据选择表现，两个时点不画连续路径，四至五条时序可用统一尺度小多图，缺失位置不补零。已有矩阵、哑铃、路线图继续复用。

这是可复用的生成与渲染能力，不代表任何主题都自动达到同等设计水平。空间形状是解释性插画；图表数据仍按独立证据读取。短材料保留适量静态排版，不强行生成复杂空间模型。

## v0.10：先选表达，再造型

长材料的空间设计现在先输出三个候选方案：直接对象、关系构图、编辑隐喻。模型根据材料的核心问题比较关联性与误读风险，再产生几何和语义开场顺序；候选及理由保存在 `report.json` 的 `spatial.selection` 中。旧报告不含这些字段也可重排，新设计必须提供方案选择和完整开场顺序。`design --feedback` 继续支持根据实看结果重设计，不改已核对正文、数值及来源。

新增圆角实体、旋转曲面与开口弧环，采用有边界的数据参数，不执行模型代码。开场按模型指定的分组顺序逐步呈现相关判断，最后收束成整体，不无限旋转。支持暂停、继续、重播，减少动态偏好下直接显示完成状态。

当前报告使用经用户同意的暖纸白、石墨黑、铜橙试用配色。`static/brand.js` 集中维护页面浅深色、图表与空间材质颜色；旧数据中的 `blue` 映射到当前强调色。它不是友车科技已确认的正式品牌规范，后续可以用正式色值替换这一个配置文件。夜间空间材质使用同配置中的补光色，保持主体与背景可辨。

## 全景图：理解全篇与独立图片分享

`overview brief` 从报告的全部章节、指标与来源准备图像设计材料；由宿主图像生成工具按内容选择关系构图，核对图片文字、期间、单位与限定后，通过 `overview attach` 接回报告。封面、阅读侧栏、顶部入口共用同一张图，支持全图、放大、PNG 下载；导出的 HTML 与 JSON 内嵌图片，离线阅读不依赖图片服务器。报告内容修改后，旧图的版本校验会阻止导出，需重做图片。

```sh
.venv/bin/python -m tools.report_studio.overview brief input-report.json --output image-brief.txt
# 将设计材料交给宿主图像生成工具，检查实际生成的图片后：
.venv/bin/python -m tools.report_studio.overview attach input-report.json --image overview.png --alt '包含全图主要判断、关键证据及边界的文字描述。' --output new-report-folder
```

图片是全篇主线摘要，不替代正文图表的可点击证据。独立图片须自带标题、期间、来源和必要边界，禁止把预测或建议画成事实。上述命令也可用于接入外部已核对图片。

## v0.17：网页一键全景图

在工作台导入或生成报告后，点击预览工具栏的“一键生成全景图”；独立本机报告页面顶部提供同一入口。程序根据全部章节、观点和事实目录调用模型设计，自动确定构图、短文案、证据引用及边界，随后调用本机已登录 Codex 的图片生成工具，并把生成图片交给图文复核模型。无需为每份报告手写生图提示词。

设计引用和数值先做校验，再由模型检查主要主题是否有正文支持、展示文案是否混入制作指令、问句是否预设未披露的成果；失败最多修订一次。图文复核检查实际成图中的数字、负号、单位、期间、结论性质与可读性，含插画里无依据的统计图。复核失败最多重画一次，仍失败则保留原报告并显示失败，不接入未通过图片。图片只接受本次生成会话目录中的 PNG，不扫描或复用其他任务的最新图片。模型图文复核不是独立审计，也不能保证发现全部错字或事实错误。

网页显示设计、生成、核对和完成状态。重复点击不重复开任务；网络中断可继续同一次任务；报告内容变化时不接回另一份报告的任务。服务重启时未完成任务明确失败，已完成报告可从磁盘恢复。每次设计与结果保存于 `workspace/report-overviews/<job-id>/`，使用现有 Codex 账户额度。离线 HTML 支持查看与下载，重新生图需要本机服务。

图文复核后的修正使用原图编辑，保留已核对的内容和构图。用户重试时，如果本地存在正文及原始材料完全相同、设计复核已通过但成图未通过的任务，则复用其设计、候选图与具体修正意见；记录继承来源，再次进行完整图文复核。材料改变则重新设计，不读取其他报告的候选图。每次点击最多两次图片生成/编辑，失败后由用户决定是否继续。

接口：`POST /api/overview` 创建任务，`GET /api/overview/{id}` 查状态，`GET /api/overview/{id}/result` 读取完成报告。设计单次上限240秒、设计文案复核180秒、图像生成360秒、图文复核180秒；超时不保证后台续跑，可明确重试。检查点中保存的设计输入、模型设计、设计复核、实际生图提示、图片会话归属、图文转录与输出用于复查。

验证：`pytest tools/report_studio/tests/test_overview_generation.py`、`node tools/report_studio/tests/overview_generate.cjs`。

## v0.18：构图选择与并列关系

全景图设计先比较三个不同信息结构，记录材料依据、误读风险和手机可读性，再把选中方案交给图片模型。原作者或反馈者提出的方案标“来源建议”，编辑推论标“分析建议”。纯机制材料允许不突出数值，不用无关大数字凑画面。

关系图允许同一泳道、同一阶段的多个并列节点，自动堆叠并扩展泳道高度；保留原节点身份和证据引用。并列项之间仍不能伪造先后箭头。节点顺序和位置不表示数量、概率或排名。

导入已有报告 JSON 后，可点击“继续复审与编排”，从原内容继续复审、读图路径和封面设计，不重生成初稿。`POST /api/continue` 使用同一流程，输入先经过证据检查；完成后清除旧版全景图，需按新内容重新生图。排查时保存的已核对初稿也可通过此入口继续。

全景图生产再由模型选择方式：精确关系使用结构绘图，物体与场景使用图片模型。结构方式输出有逐字依据的节点、请求线、无方向关联线、阻断入口及范围包含；程序负责中文排印和几何，关联线自动避开无关节点，整体状态以外围虚线标明。分享要点由模型按原panel顺序压缩，保留观点性质；完整证据留在报告中。每种方式都继续进行成图复核。

结构方式复用 Pillow，无额外绘图服务；需要本机中文字库（macOS Heiti/Songti 或 Linux Noto CJK），也可通过 `REPORT_CJK_FONT` 指定字体。缺失字库时报错，不输出方框字。结构、几何和复核结果保存于生成任务目录。结构检查证明引用与几何约束成立，不能证明全部语义或审美达标。

## v0.28：技能驱动选图与精确数值分享图

[Business Visual Storytelling（商业研究的图形表达）](skills/business-visual-storytelling/SKILL.md) 的目录与规则由生成、复审、分享图规划共同读取。`qualified_dot` 对同尺度的报告值、约数及单侧界限分别编码；限定词有原句校验，支持来源下钻、逐项读图与重播。单行两期份额可用 `comparison`，不再为凑行加入异口径指标。

全景图标准 2.8 增加数量图的精确绘制分支：模型仍自行比较三种构图并选择标题、事实与业务启发；当选择 `quantitative_comparison`，且2—3项数值来自同一个 `qualified_dot`、支撑文案不超过3条、口径文字足够简洁时，按原值计算共同数轴，绘制全新1600×2000 PNG。坐标等距、符号与中文不由生图模型估画，保存 `quantitative-geometry.json` 和 `render-engine.json` 供复查。其余主题继续走图片模型，所有结果仍经图文复核、版本绑定和人工检查。该分支没有开放任意图形或任意代码执行，也不是所有图种的通用海报引擎。

继续使用网页的“继续复审与编排”“一键生成全景图”，不为单份报告手写提示词。旧报告保持不变；CLI 修改内容时清除旧图片绑定。边界、来源过长导致安全区不足时明确失败，不裁掉关键文字。此本机精确排版依赖 Pillow 与中文字库，部署到其他主机须核对字体。

## v0.29：编辑式分享图与分阶段读图

模型可为数量比较选择 `reader_design.numeric_layout`：非负的两三项数据用 `paired_columns`，其他情况保留 `horizontal_scale`。并置主图保留真实零点、下限开放顶端、大读数，压缩重复段落为一个读者启发；统计期间由模型通过 `chart_caption` 生成并参与数值校验。竖版 1600×2000、32像素来源，仍经过模型图文复核。

限定值图新增从零点展开的量值线，并按标尺、量值、界限、读数先后显示；减少动态效果和打印时保持静态。两个对象采用大读数版式，多对象保留紧凑对齐；不会把约数动画成假精确数。依然不根据增速差编造库存或转化率。

## v0.30：数据信号与业务解释组合

新增 `evidence_composite` 分享图语法：模型同时设计 signal（读数）、explanation（独立业务解释）、implication（受众启发）。每项必须关联有原文依据的锚点与批准内容，全部内容进入绘制；不允许把数字或行动建议重复登记成业务解释，至少两项图形论证检查数据与业务含义。

该语法使用模型选择的连续注释式构图并经过实际图片复核，不进入单一数量海报引擎。比例不足时保留概念示意，不伪造漏斗、库存量或转化率。构图选择、解释覆盖和源引文校验通用于非汽车材料；更换主题仍需核对实际生成结果。

复核区分局部执行错误和构图本身失效。后者触发一次模型重新设计：事实、文案、来源与引文保持不变，合法锚点通过输出枚举约束；新构图从空白画布生成，不继续编辑已经被否定的图片。机制示意可以表达定性时间错位，但不添加日期或时长。原稿与失败记录保留，仍未通过时不替换报告。
